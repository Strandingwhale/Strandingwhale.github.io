# 地下城引擎 · S2–S3 开发记录

> 项目：地下城引擎（2D 瓦片地下城 / Roguelike 方向）
> 记录时间：2026-11-22
> 版本：V0.1.2
> 平台：Windows + MinGW-w64（`D:\mingw64`，g++ 15.2.0）+ Trae

S2 没什么可说的，就是几个结构体和五个小函数。S3 走了十一步，中间返工两次：一次是 GL 函数加载，一次是资源路径。两次都是我先把方案定死了再动手，撞了墙才换。这里把过程和撞墙的地方记下来。

## 四、S2：数学类型

只做了最简版。文档里 Arena、Pool、`Handle`、`SlotMap` 全部往后推——现在没有性能热点，也没有真实需求，做了也是猜。

`core/math/Types.h` 是纯 POD，手写，不引 glm：

```cpp
struct Vec2  { float x, y; };
struct Vec2i { int x, y; };
struct Rect  { float x, y, w, h; };
struct Recti { int x, y, w, h; };

Vec2i RoundToGrid(Vec2 world, float cellSize);
float Length(Vec2 v);
Vec2  Normalize(Vec2 v);
bool  RectContains(const Rect& r, Vec2 p);
bool  RectContains(const Recti& r, Vec2i p);
```

实现放 `Types.cpp`，glm 只在那里出现。

三件事我当初是刻意这么定的：

**头文件不 include glm。** glm 在 `engine/CMakeLists.txt` 里是 PRIVATE include，不往外传。要是 `Types.h` 里写了 `#include <glm/vec2.hpp>`，`game` 立刻编译失败，或者你也可以给 game 也配上 glm 路径——但那等于把第三方库的路径写进了游戏层，后面换数学库要动的地方就多了。

**`Vec2` 和 `Vec2i` 不给隐式转换。** 想从世界坐标拿格子，必须写 `RoundToGrid()`。多写一行，换的是"把格子数当像素传进去"这种 bug 在编译期就死掉。这种错误在运行时表现为瓦片偏半格，肉眼要盯很久。

**不放 `dg::math` 子命名空间。** `Vec2` 是全项目词汇表，`map`、`ecs`、`ui`、`serialize` 都要用。放子命名空间的结果是二十个文件里都在写 `using namespace dg::math`，多一层却没有隔离意义。

放在 `core/math/` 而不是 `engine/math/`，也是同一个道理：`core` 是"谁都能依赖的地基"，`Vec2` 必须在最底层。要是它和 `renderer` 平级，`map` 依赖 `renderer` 的假依赖马上出现。

## 五、S3：渲染器

### 5.1 上下文

```cpp
SDL_GL_SetAttribute(SDL_GL_CONTEXT_MAJOR_VERSION, 3);
SDL_GL_SetAttribute(SDL_GL_CONTEXT_MINOR_VERSION, 3);
SDL_GL_SetAttribute(SDL_GL_CONTEXT_PROFILE_MASK, SDL_GL_CONTEXT_PROFILE_CORE);
SDL_GL_SetAttribute(SDL_GL_DOUBLEBUFFER, 1);
SDL_GL_SetAttribute(SDL_GL_DEPTH_SIZE, 24);
```

选 core profile 是为了断退路。core 里没有 `glBegin/glEnd`，想画东西必须走 VBO 和 shader，从第一天就是"能合批"的形态。用 compatibility 的话很容易一路 `glBegin` 画下去，到第 100 个精灵才发现要重写。

### 5.2 GL 函数加载（返工一次）

第一版是自写 loader：手工补 `typedef`、补枚举、声明 `extern` 函数指针，再用 `SDL_GL_GetProcAddress` 一个个查。

问题不在麻烦，在于漏。GL 的函数和枚举几千个，手写必然漏，漏了之后崩在驱动内部，栈上全是驱动地址，看不出是谁调的。

第二版换 glad2，一行接进去：

```cpp
gladLoadGL(reinterpret_cast<GLADloadfunc>(SDL_GL_GetProcAddress));
```

`rhi/GL.h` 剩下错误检查：

```cpp
void CheckGLError(const char* file, int line);
#define DG_GL_CHECK() CheckGLError(__FILE__, __LINE__)
```

这类东西的价值全在"不漏"，机械正确性靠抄比靠写实在。

### 5.3 Shader 与热重载

```cpp
bool LoadFromFiles(vert, frag);
void PollHotReload();   // 每帧调，内部限频 200ms
void Use() const;
unsigned int Id() const;
```

三个地方要注意：

一是限频 200ms。`PollHotReload` 每帧都被调，但真去查文件时间戳最多每秒五次。Windows 上频繁 stat 会拖慢编辑器保存。

二是顺序：先编译新的，成功才删旧的。反过来就是"保存一个半成品，画面立刻黑掉"。

三是失败必须把 glsl 的编译日志原文打出来。写错一个 `}` 的时候日志是：

```
ERROR: 0:9: '}' : syntax error
[shader] 热重载失败，继续使用旧 shader
```

`0:9` 是行号，看一眼就知道改哪。

### 5.4 资源路径（返工，这次花了最久）

第一版用 CMake 的 `add_custom_command` 把 `assets/` 拷到 exe 旁边，程序读那份副本。

结果改源码里的 shader 没反应。程序读的是副本，副本只在构建时更新，热重载等于白做。

改成两条路径：

| 函数 | 指向 | 用在哪 |
|---|---|---|
| `Paths::BaseDir()` | exe 目录，可写 | 日志、存档 |
| `Paths::AssetDir()` | 只读资源根 | 美术、配置、shader |
| `Paths::Resolve("res://…")` | AssetDir | 所有读资源 |
| `Paths::Exe("logs/…")` | BaseDir | 所有写文件 |

`AssetDir()`：

```cpp
#ifdef DG_ASSET_ROOT
    return DG_ASSET_ROOT;          // Debug：编译期注入源码目录
#else
    return BaseDir() + "/assets";  // 发布：exe 旁边的 assets
#endif
```

CMake 里只在 Debug 注入：

```cmake
target_compile_definitions(engine PRIVATE
  $<$<CONFIG:Debug>:DG_ASSET_ROOT="${CMAKE_SOURCE_DIR}/game/assets">)
```

实测两条路径都对：Debug 下 `assets=D:/地下城引擎/game/assets/`，改 frag 一秒内变色；Release 下 `assets=.../build-release/bin/assets/`，说明发布包能脱离源码目录跑。

同一轮还清了三个旧账：`SDL_free(const_cast<char*>)` 的未定义行为、`EnsureDir` 只建一层（换 `create_directories`）、`Window` 越权管 `SDL_Init/Quit`（移进 `EngineInit/EngineShutdown`）。

### 5.5 纹理

读文件，统一转 RGBA8，传显存。四个坑全踩了：

| 坑 | 现象 | 处理 |
|---|---|---|
| stb 默认不翻转 | 图上下颠倒 | `stbi_set_flip_vertically_on_load(1)` |
| stb 内部用 `fopen` | `D:\地下城引擎\` 这种中文路径直接打不开 | 自己用 `u8path` + ifstream 读字节，再 `stbi_load_from_memory` |
| 没设 `GL_TEXTURE_MIN_FILTER` | 整张图纯黑 | 默认 mipmap 过滤但没生成 mip 链，采样全是 0。设成 `GL_NEAREST` |
| `GL_UNPACK_ALIGNMENT` 默认 4 | 宽度不是 4 倍数的图错位 | `glPixelStorei(GL_UNPACK_ALIGNMENT, 1)` |

另外 `STB_IMAGE_IMPLEMENTATION` 只能在一个 `.cpp` 里展开，现在只在 `Texture.cpp`。

上传用 `GL_RGBA8` + `GL_NEAREST` + `GL_CLAMP_TO_EDGE`。像素风必须最近邻，不然边缘糊成一团；CLAMP 是防止 UV 贴到 0 或 1 时采到对边的像素。

### 5.6 合批

顶点格式二十字节：

```cpp
struct Vertex {
    float x, y;
    float u, v;
    unsigned char r, g, b, a;
};
```

颜色用 8 位而不是 float，是因为 8192 个四边形就是 32768 个顶点，`ubyte×4` 比 `float×4` 省 393KB，而 UI 染色、受击闪白、视野压暗这些用 8 位通道够了。

索引一次性预生成，每个四边形 `0,1,2, 2,3,0`，base 每次加 4，`GL_STATIC_DRAW` 建完不动。绘制只传顶点。

`Flush()` 用孤儿化：

```cpp
glBufferData(GL_ARRAY_BUFFER, vboCapacity_, nullptr, GL_DYNAMIC_DRAW);  // 丢掉旧内容
glBufferSubData(GL_ARRAY_BUFFER, 0, bytes, vertices_.data());           // 写新的
```

先让驱动换一块新显存，是为了避开"上一帧 GPU 还在读、这一帧 CPU 又要写"的隐式同步。有同步的话帧时间会突然从 4ms 跳到 10ms，而且只在某些机器上跳。

实测：

| 场景 | 绘制调用 |
|---|---|
| 1000 格瓦片 | 1 |
| 8190 + 2 = 8192（正好满批） | 1 |
| 9000 + 2 = 9002 | 2（8192 + 810） |

混合状态在创建设备时设一次：

```cpp
glEnable(GL_BLEND);
glBlendFunc(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA);
```

这里被自己的测试图骗过一次。给半透明白条测试图时用 GDI+ 的 `SolidBrush` 画，GDI+ 在画的时候就把颜色合成进去了，PNG 里存下来的是 `A=255, RGB=(144,173,244)`——看着像半透明白，实际是实心淡蓝。后来改用 `SetPixel` 逐像素写 `A=110` 才测出真 alpha。

验收也得换方法：别去比"白条颜色有没有变"，要拿两个 sprite 互相叠。`0.431×255 + 0.569×(60,110,235) = (144,173,244)`，实测对上才算混合通了。

### 5.7 相机

```cpp
const glm::mat4 m = glm::ortho(left, right, bottom, top, -1.0f, 1.0f);
```

`bottom` 传大的 y、`top` 传小的 y，这一处反着传是为了把"世界 y 向下"翻成 NDC 里的 y 向上。

`zoom` 的含义是"一个世界单位占几个像素"，视野大小等于 `viewport / zoom`。

`WorldToScreen` / `ScreenToWorld` 必须和 `ViewProj` 共用一套公式，否则鼠标点和画面错开。这两个函数到 S3 收尾做鼠标指格子的时候才第一次真用上。

上传矩阵时 `glUniformMatrix4fv(..., GL_FALSE, ...)`，转置传 `GL_FALSE`。glm 默认列主序正好是 OpenGL 要的排布。这里传反会得到"镜像 + 错位"的画面，很容易被误判成相机公式写错了。

### 5.8 图集

测试图 128×128，8×8 = 64 格，每格 16×16，颜色各不相同，外围一圈深色边，右下角一个角标——角标是用来判断 UV 有没有上下颠倒的，翻了的图角标会跑到左上。

`atlas.txt` 一行一块：

```
floor_stone 0 0 16 16 0
wall_top    16 0 16 16 1
```

`Atlas` 里有三件事：

越界校验，`x+w <= tw && y+h <= th`，不满足就报错拒绝加载。图集描述错一个数字，表现是"某块瓦片显示成隔壁的图"，靠肉眼几乎发现不了，只能在加载期拦。

`FindId()` 启动时查一次，之后只用 `int`。早期是每次画瓦片都 `UvByName("floor_stone")`，线性查找加字符串比较，满屏 800 个瓦片就是每秒 48000 次 `strcmp`。

`solid` 列是提前做的（原来是 S4 的事）：每行末尾加一个可选布尔，告诉引擎这块挡不挡路。碰撞数据跟着美术走，而不是在代码里写 `if (tile == 5 || tile == 12)`。

### 5.9 瓦片地图与裁剪

`map::TileMap` 只有一个二维 `int` 数组，`-1` 是空。

`Set` 越界忽略，`Get` 越界返回 `emptyTile`。生成器写到地图外、渲染扫到地图外，都不该崩。

裁剪范围由相机反算：

```
x0 = floor((center.x - halfW) / tileSize)
x1 = ceil ((center.x + halfW) / tileSize) - 1
```

`ceil` 后面那个减一：右边界正好落在格线上时，那一格其实看不见，不减会多画一整列。

200×200 地图、1280×720 视口、zoom=1，视野是 80×45 格：

| 相机位置 | 提交瓦片数 |
|---|---|
| 起点（房间内） | 976 |
| 一路向右 | 1024 → 1124 → 942 → 816 → 672 → 406 → 128 → 0 |
| 视野完全出地图 | 0，此时绘制调用也是 0 |

最后一行值得单独确认：空批次是不产生绘制调用的，不是"画了 0 个顶点"。

### 5.10 从渲染器改成绘制入口（结构返工）

走到这里 `core/Renderer` 已经变成一团：清屏、viewport、swap、shader、还有 `DrawTileMap(map, atlas, tileSize, sprites, count)` 这种专为一种东西写的函数。

问题很明显：每加一种东西就得多一个 `Draw*`，`DrawPlayer`、`DrawMonster`、`DrawItem`、`DrawParticles` 会一直长下去。而且引擎开始认识"瓦片地图""玩家"这些游戏概念，engine/game 的边界就没了。

拆成四层：

```
rhi/GlDevice            清屏 / viewport / swap / GL 全局状态 / 错误检查
renderer/BatchRenderer  攒批、按纹理自动分段、一次 drawElements
renderer/Sprite         纯数据，里面没有 GL 调用
core/Renderer           只做帧编排：BeginScene → Submit… → EndScene
```

调用形态变成：

```cpp
renderer.BeginScene(camera);
renderer.Submit(sprite);
renderer.EndScene();
```

`EndScene` 里排序、分组、绘制、交换缓冲。调用方只管说要画什么，不管怎么画。

`Sprite` 定稿：

```cpp
struct Sprite {
    const rhi::Texture* texture;
    Rect  src;
    Vec2  center;
    Vec2  size;
    Color color;
    Layer layer;        // Terrain/Object/Unit/Effect/Debug/UI
    bool  flipX, flipY;
    bool  screenSpace;  // true 表示 center 是屏幕像素
    float rotation;     // 弧度，绕 center 顺时针
};
```

排序：

```cpp
std::stable_sort(sprites_, [](a, b) {
    if (a.layer != b.layer) return int(a.layer) < int(b.layer);
    return a.center.y < b.center.y;   // y 大的后画，压在上面
});
```

用 `stable_sort` 而不是 `sort`，是因为同一 y 的两个物件每帧换前后会闪。只有一张图集的时候，排序不会增加绘制调用，只是改提交顺序。

`Layer::Debug` 放在 `Effect` 之后、`UI` 之前，这样世界里的调试框盖得住单位，又不会盖住 HUD。

顺带说一句文档里那条"顶点带 texIndex，16 槽一个 draw call"——GL 3.3 做不到。GLSL 3.30 里 `sampler2D uTex[16]` 的索引必须是常量表达式，顶点传下来的索引不能拿来动态索引入 sampler 数组。真要做只能上 `GL_TEXTURE_2D_ARRAY`。所以改成按纹理分段 flush：`BatchRenderer` 记住当前纹理，换纹理就 Flush。这样绘制调用的上限是这一帧用到的纹理数，单图集时还是 1。

### 5.11 屏幕通路

一开始所有 Sprite 都走同一套 `uViewProj`，于是文字跟着相机跑，滚轮一滚字就变大。HUD 得钉在屏幕上。

`EndScene` 分两趟：

```cpp
// 世界：相机矩阵
glUniformMatrix4fv(viewProjLocation_, ..., camera.ViewProj(...));
<< screenSpace == false 的 >>  Flush();

// 屏幕：像素正交
glUniformMatrix4fv(viewProjLocation_, ..., screenCamera.ScreenProj(...));
<< screenSpace == true 的 >>   Flush();
```

屏幕那趟用的是"像素到 NDC"的正交投影，`left=0, right=viewportW, bottom=viewportH, top=0`，不是单位矩阵。这样写 UI 坐标可以直接写 `{8, 8}`，不用自己算 NDC。

代价是每帧最多多一次绘制调用。正常场景 `drawcalls=2`（世界一次、屏幕一次）；开调试绘制是 3，因为屏幕趟里图集和字体是两种纹理，中间会断一次批。

这块要是拖到 S7 才补，物品栏、日志面板、鼠标光标都得返工。现在补进去几乎没成本。

### 5.12 旋转

`rotation` 完全在 CPU 上算：

```cpp
const float c = cos(rotation), s = sin(rotation);
// 每个角相对 center 的 (dx,dy) → (dx*c - dy*s, dx*s + dy*c)
```

shader 一个字没改。顶点本来就是 CPU 算好的世界坐标，旋转只是算顶点位置。y 向下的坐标系里，`atan2(dy, dx)` 的结果正好就是"顺时针为正"的角度，不用取反——第一次拿它画线段的时候确认过。

### 5.13 位图字体

没上 FreeType，也没碰中文（那是 S7 的事）。第一版就是一张 8×16 的 ASCII 图集：95 个可打印字符，16 列 6 行，输出 128×96。字形必须是纯白加 alpha，颜色靠顶点色染，字形自己带颜色的话染出来是脏的。

`renderer/BitmapFont`：

```cpp
bool Load(path, cellW=8, cellH=16, columns=16, firstChar=32);
Rect Glyph(char c) const;
int  Advance() const;
int  LineHeight() const;
```

`Text.h` 一个自由函数逐字符 `Submit`。

三条规矩，全都踩过：

只允许整数倍缩放。1.5 倍会把 8px 的硬边糊成灰边，所以 `scale` 进来先取整。

坐标必须 `floor`。字形落在半像素上会同时采到两个纹素，边缘发灰、字发虚。

空格不画，但必须推进一格。不然 `"HP: 100"` 挤成一坨。

第一版图集的字太小。逐像素量了一遍，`A` 的墨迹只有 6px 高（`y[4-9]`），塞在 16px 格子里，上下各空一大截，看着又小又稀。重按 Consolas 13px 生成：

| | 原版 | 重生成 |
|---|---|---|
| `A` / `0` 墨迹 | `y[4-9]`，6px 高 | `y[4-11]`，8px 高 |
| `H` 横向 | `x[2-5]` | `x[1-5]` |
| `g` 下伸 | — | 到 `y[14]`，不切底 |
| 半透明边 | 0 | 0（纯二值 alpha） |
| 不透明像素 | 1129 | 1427 |

"字看着糊"和"字看着小"是两回事，得分开查。糊是采样问题（坐标没取整、用了线性过滤）；小是图集生成时字号就不够。混在一起改，改完还是不对。

### 5.14 调试绘制

```cpp
void Init(const rhi::Texture& tex, const Rect& whiteUv);
void Line(Renderer&, Vec2 a, Vec2 b, float thickness, Color, bool screenSpace=false);
void RectOutline(Renderer&, const Rect&, float thickness, Color, bool screenSpace=false);
void FillRect(Renderer&, const Rect&, Color, bool screenSpace=false);
void CircleRing(Renderer&, Vec2 center, float radius, int segments, float thickness, Color);
```

`DebugDraw` 不认识 Atlas，只收一个纹理引用和一个白色 UV 矩形。game 层构造时传 `atlas.TextureRef()` 和 `atlas.Uv(player.tile)`——就是那块纯白格。于是一个白方块加顶点色加旋转，线、框、圆环就都有了，不用为调试再加贴图，engine 也不用去认识 game 的图集。

三个实现细节：

线段就是旋转过的细长矩形，`size = {len + thickness, thickness}`，多出来那段把首尾的方角缺口补上。

矩形框四条边得错开。现在四条各缩半个线宽，拐角会叠出一个 `t×t` 的方块——alpha 是 255 时看不出来，画半透明的框（比如那条 `{255,255,255,180}`）角上就明显亮一块。改法是横向两条满宽、纵向两条在 y 方向缩进 `thickness`。

圆环半径要放大 `1/cos(π/segments)`。多边形内切于圆，按半径直接描点看着会偏小，补偿之后顶点才落在圆上。24 段够用。

## 六、几个决定

| 决定 | 为什么 | 代价 |
|---|---|---|
| OpenGL 3.3 core，不用 `SDL_Renderer` | 2010 年以后的硬件都支持；core 强制走 VBO 和 shader | 自己做 RHI、矩阵、热重载 |
| glad2 代替自写 loader | 函数枚举几千个，手写必漏，漏了崩在驱动里 | 多一个第三方目录 |
| 顶点色 8 位 | 每顶点省 12 字节，8 位够用 | 得记得 `normalized=GL_TRUE` |
| NEAREST + CLAMP_TO_EDGE | 像素风不能线性过滤 | 非整数缩放会串色，见遗留 2 |
| 放弃 16 纹理槽，改按纹理分段 | GLSL 3.30 的 sampler 数组不能动态索引 | 绘制调用数等于纹理数 |
| `Submit(Sprite)` 而不是 `DrawSprite` 直连 | 引擎只认识四边形，不认识瓦片地图和玩家 | 多一层间接，多一个结构体 |
| `stable_sort` | 同 y 的物件不能每帧换前后 | 每帧一次临时分配，1 万项约 440KB |
| 屏幕/世界两条通路 | HUD 必须钉在屏幕上 | 每帧最多多一次绘制调用 |
| 旋转放 CPU | shader 不用改，顶点本来就是世界坐标 | 每个四边形多四次 sin/cos，可以忽略 |
| 位图字体，不上 FreeType | 现在只要 ASCII | 只支持整数倍缩放 |
| 调试用图集白格当笔刷 | 不加贴图，engine 不依赖 game 的图集 | 圆是折线近似 |

## 七、踩过的坑

| # | 现象 | 原因 | 处理 |
|---|---|---|---|
| 1 | GL 调用崩在驱动里，栈上没有自己的代码 | 自写 loader 漏函数、漏枚举 | 换 glad2 |
| 2 | 改 shader 源码画面不变 | assets 被拷到 exe 旁，程序读副本 | 资源根双轨（`DG_ASSET_ROOT`） |
| 3 | 中文路径的图加载失败 | stb 内部走窄字符 `fopen` | `u8path` + ifstream + `stbi_load_from_memory` |
| 4 | 纹理整张纯黑 | 没有 `GL_TEXTURE_MIN_FILTER`，默认 mipmap 但没 mip 链 | 设 `GL_NEAREST` |
| 5 | 宽度非 4 倍数的图错位 | `GL_UNPACK_ALIGNMENT` 默认 4 | `glPixelStorei(GL_UNPACK_ALIGNMENT, 1)` |
| 6 | 半透明条看着像实心浅色，测不出 alpha | 测试图是 GDI+ 画的，画的时候已经合成（`A=255`） | `SetPixel` 写 `A=110` 重做；验收改成两个 sprite 互叠 |
| 7 | 染色没生效 | `GL_UNSIGNED_BYTE` 必须 `normalized=GL_TRUE` | 改 TRUE，实测 `(230,21,21)` |
| 8 | 热重载后画面变白或变暗 | uniform 是 program 的状态，换 program 全丢 | 每帧 `Use()` 后重设；location 按 program id 缓存 |
| 9 | 9000 个精灵出现 2 次绘制，以为有 bug | 容量 8192，满批必须断 | 正常，8192 + 810 |
| 10 | 瓦片之间有彩色细缝 | 非整数 zoom + 图集没 padding + NEAREST | 还没修，见遗留 2 |
| 11 | 文字边缘发灰、字发虚 | 字形落在半像素上，又允许小数缩放 | 坐标 `floor`，缩放取整 |
| 12 | 文字又小又稀 | 图集生成时字号就不够，墨迹只有 6px | 重生成，8px |
| 13 | `glViewport` 和窗口尺寸不一致时画面缩在左下角 | `SDL_GetWindowSize` 是逻辑尺寸，DPI 缩放下不等于像素尺寸 | 还没修，见遗留 1 |
| 14 | 矩形框拐角比边线亮 | 四条线各缩半宽，拐角叠出方块 | 还没修，见遗留 3 |

第 2 和第 6 最该记。一个是"文件存在不等于你读到的是改的那份"，另一个是"测试工具本身也会骗你"。

## 九、遗留

按该先修的顺序：

1. **`GlDevice` 用的是 `SDL_GetWindowSize`**，应该换成 `SDL_GetWindowSizeInPixels`。Windows 缩放在 125% 或 150% 时（笔记本默认就是这个），逻辑尺寸不等于像素尺寸，`glViewport` 和 `ScreenToWorld` 会一起错位。一行能修，但影响面最大。
2. **图集没有 padding**，非整数 zoom 下相邻瓦片串 1px 色。两条路：`Atlas::Uv` 里做半纹素内缩（马上见效，每格丢半像素），或者等 S4 的离线图集工具生成带 1px padding 的图集。
3. **`RectOutline` 拐角重叠**，半透明框的角会亮一块。
4. **`BitmapFont` 自己持有纹理，`SubmitText` 还单收一个 `texture`**，冗余。接第二个字体时会出现字和纹理对不上的 bug。改成内部取 `font.TextureRef()`。
5. **不支持换行、行距、对齐**。现在只有单行左对齐，S7 做面板时补。
6. **没有按纹理分组**。屏幕通路里图集和字体交替提交会多断一次批。真要优化在 `Renderer` 里做二次分组，现在不值得。
7. **`stable_sort` 每帧临时分配**，1 万项约 440KB。做"30 分钟内存曲线是平的"那条验收时换成复用成员的稳定归并。
8. **S3 还有三项验收没跑**：1 万精灵压测（F2）、改分辨率与全屏、Release 长跑。
9. **`engine/CMakeLists.txt` 还是 `GLOB_RECURSE` 收全目录**。等 `engine/tools/` 出独立 exe 的 `main.cpp` 就会撞，最迟 S11 前改显式列表。
10. **`game/main.cpp` 里的玩家和碰撞是临时探针**。按"先写引擎、再写游戏"的顺序，这段冻结，等 S5 的实体和 S6 的碰撞做好就替掉，不再往前加玩法。
11. 十二个预留空目录和 `tests/` 没进 git（git 不跟踪空目录），克隆下来会消失。
12. `game.exe` 还是控制台子系统，黑色控制台窗口挡在游戏窗口前面。Release 该按配置切 `WIN32_EXECUTABLE`。

## 十、下一步

S3 剩三项验收，跑完打 `V0.2.0`，然后进 S4。

S4 的目标是"改一张美术，重开或热重载就生效，代码零改动"。顺序：

1. 引入 nlohmann/json，header-only，单文件放 `third_party/nlohmann/`。注意 `raw.githubusercontent` 在本地不通，别指望 curl。
2. 写 `assets.json`，把现有资源全登记进去：`tex://atlas`、`tex://font`、`tex://missing`、`atlas://tiles`、`shader://basic`、`font://hud`。
3. `AssetRegistry`：`Load`、`GetTexture/GetAtlas/GetFont/GetShader`、占位兜底、错误行号。
4. `main.cpp` 改成从 registry 取，删掉所有 `Paths::Resolve("res://...")` 字面路径。
5. 验收：把 `assets.json` 里 `tex://atlas` 的 path 改成一个不存在的路径，重开应该看到粉黑格加一行指出第几行的错误，而不是崩。
6. 热重载（F5），纹理和 JSON 都要监听。
7. 离线图集工具：读 Aseprite 导出的 json，生成带 padding 的图集和 UV 表。

第 4 步做完，项目里就不该再有硬编码的资源路径了。

占位图已经放在 `game/assets/textures/missing.png`（16×16 粉黑棋盘格）。约定是 `GetTexture` 在 ID 不存在或读文件失败时返回占位图，不返回 `nullptr`——调用方永远不用判空。如果返回空指针，你会在几十个调用点写 `if (!t) return;`，而那些 `return` 里往往顺手吞掉了半个画面。
